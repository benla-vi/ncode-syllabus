# צ'קליסט תפעול: ClickUp כתחנת אישור

> כל סיפור = משימה ב-ClickUp. בן מאשר בגרירה בין סטטוסים. שום כתיבת תסריט לא
> מתחילה אוטומטית — רק כשבן אומר בצ'אט. הסקריפטים ב-`pipeline/clickup_export.py`
> הם שכבת התרגום קבצים→payloads בלבד; קריאות ה-MCP (`clickup_create_task` וכו')
> מבוצעות ע"י קלוד בסשן, לפי הצ'קליסט הזה.

---

## 1. הקמה חד-פעמית

1. `clickup_get_workspace_hierarchy` — למפות את הבורד/החללים הקיימים אצל בן.
2. בחירת רשימה קיימת או יצירת רשימה חדשה בשם **"🎬 מפעל הסרטונים"** דרך
   `clickup_create_list`, עם הסטטוסים:

   | סטטוס | משמעות |
   |---|---|
   | 📥 תפריט | סיפור חדש מהריצה היומית, ממתין לבחירת בן |
   | ✅ אישרתי | בן בחר — מוכן לשלב 2 (כתיבת תסריט) |
   | ✍️ בכתיבה | תסריטאי+מבקר עובדים על הסיפור |
   | 📝 תסריט מוכן | התסריט המלא כתוב בתיאור המשימה |
   | 🎥 צולם | בן צילם את הסרטון |
   | 🚀 פורסם | הסרטון באוויר |
   | 🗄️ ארכיון | נפסל / לא נבחר |

3. **הערה חשובה:** אם יצירת סטטוסים מותאמים לא זמינה דרך ה-MCP (חלק
   מהאינטגרציות של ClickUp לא חושפות את זה) — ליצור את הרשימה **ידנית ב-UI**
   לפי הטבלה למעלה, ואז לעדכן כאן את ה-ids.

4. טבלת אמת — למלא אחרי ההקמה:

   | שדה | ערך |
   |---|---|
   | `workspace_id` | |
   | `space_id` | |
   | `list_id` (🎬 מפעל הסרטונים) | |
   | `status: 📥 תפריט` | |
   | `status: ✅ אישרתי` | |
   | `status: ✍️ בכתיבה` | |
   | `status: 📝 תסריט מוכן` | |
   | `status: 🎥 צולם` | |
   | `status: 🚀 פורסם` | |
   | `status: 🗄️ ארכיון` | |

## 2. ריצה יומית — שלב 1 (מחקר → משימות בתפריט)

1. סקאוט → מיזוג → דירוג — בדיוק כמו היום (`pipeline/run_daily.py`, ללא
   `--pick`/`--auto`), מייצר `output/<date>/01-stories.json` ו-`02-ranking.json`.
2. **עדשה שישית — אאוטליירים:** בנוסף לחדשות, הסקאוט (לפי
   `prompts/01-news-scout.md`, סעיף "שכבת אאוטליירים") סורק את דפי הייחוס
   מ-`config.yaml → news.research_channels`, מחזיר 3-5 פורמטים מנצחים + הצעות
   מתיחה לנישה, והם נכנסים לתפריט כסיפורים עם `source_outlier`. בתיאור המשימה
   שנוצרת מופיעה שורת "🧬 פורמט מוכח: ..." (אוטומטית ע"י `clickup_export.py`).
   אאוטליר יכול להיות גם וידאו-ערך/שיטה — ואז ההצעה היא תסריט הדרכה בפורמט
   וידאו-ערך.
3. `python pipeline/clickup_export.py <date>` — מייצר
   `output/<date>/clickup-tasks.json` (מערך payloads, אחד לכל סיפור).
4. לכל payload ברשימה: `clickup_create_task` עם `name`, `markdown_description`,
   `tags`, סטטוס **📥 תפריט** ברשימת "🎬 מפעל הסרטונים".
5. `git add -f output/<date>` + קומיט — הקבצים מקומיים ל-`output/` תחת
   `.gitignore`, ולכן צריך `-f` כדי לשמר אותם כדאטהבייס הקנוני.

---

## 3. אישור

בן גורר משימות מ-📥 תפריט אל **✅ אישרתי** (או ישר ל-🗄️ ארכיון אם לא מעניין
אותו). שום כתיבה לא מתחילה אוטומטית מהגרירה עצמה — היא רק מסמנת כוונה.

---

## 4. שלב 2 — רק כשבן אומר בצ'אט "תכתוב את X" / "קדימה על הנבחרים"

1. `clickup_filter_tasks` על הרשימה עם סטטוס **✅ אישרתי**.
2. לכל משימה שחוזרת: לחלץ את `run_key` מתוך שורת ה-`run_key: <date>#<id>`
   בסוף התיאור.
3. לטעון את הסיפור המתאים מ-`output/<date>/01-stories.json` לפי `<id>`.
4. להעביר את המשימה לסטטוס **✍️ בכתיבה**.
5. להריץ סוכן תסריטאי (אופוס, `prompts/03-scriptwriter.md`) ואז סוכן מבקר
   (אופוס, `prompts/05-critic.md`) על כל סיפור.
6. לשמור את התוצאה כ-`output/<date>/script-NN.json`.
7. `python pipeline/clickup_export.py <date> --scripts --ids <id1,id2,...>`
   (הסדר של ה-ids חייב להתאים לסדר קבצי ה-script-NN.json) — מייצר
   `output/<date>/clickup-script-updates.json`.
8. לכל עדכון: `clickup_update_task` עם `markdown_description` = התסריט המלא,
   ואז `clickup_create_comment` עם התקציר הקצר.
9. להעביר את המשימה לסטטוס **📝 תסריט מוכן**.
10. קומיט (`git add -f output/<date>`).

---

## 5. אחרי צילום / פרסום

בן מזיז ידנית ל-🎥 צולם ואז ל-🚀 פורסם. אפשר להזרים מדדי ביצועים (צפיות,
לייקים, קומנטים) כתגובות (`clickup_create_comment`) על אותה משימה — היסטוריה
אחת למקום אחד לכל סיפור.

---

## 6. טבלת אמת-מקור

| שכבה | תפקיד |
|---|---|
| **קבצים + git** (`output/<date>/*.json`) | דאטהבייס קנוני — כל מה שנוצר תמיד קיים כאן קודם |
| **ClickUp** | state, אישורים, ותצוגה לבן — לא מקור אמת לתוכן עצמו |
| **גוגל דוקס** | לא בזרימה החדשה — הוחלף ע"י תיאור המשימה ב-ClickUp |

אם יש סתירה: הקובץ המקומי מנצח. ClickUp הוא עותק תצוגה, לא מסד הנתונים.

---

## 7. Fallbacks

- **אין הרשאה ליצור שדות מותאמים (custom fields)** — לא נורא, זה כבר המצב
  היום: הכל עובר דרך תגיות (`tags`) ותיאור (`markdown_description`), כולל
  שורת ה-`run_key` שמשמשת כמפתח חיפוש.
- **`run_key` לא נמצא / לא ניתן לפענוח** מתוך תיאור המשימה — להצליב מול
  `output/<date>/01-stories.json` לפי דמיון בכותרת (`headline_he`) במקום.
- **סטטוסים מותאמים לא נתמכים דרך ה-MCP** — ליצור את הרשימה ידנית ב-UI לפי
  הטבלה בסעיף 1, ולעדכן את ה-ids בטבלת האמת שם.
